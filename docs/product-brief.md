# Product brief

## Product

Defuse Protocol is a local, virtual-credit slot simulator wrapped in an original realistic tactical-thriller presentation. It exists to help curious users explore how slot configuration affects long-run behavior while still feeling like a polished game.

## Audience

- Hobbyists learning probability and slot design
- Developers experimenting with deterministic simulations
- Players curious about RTP, hit rate, volatility, and bonus frequency

It is not intended for real-money play, commercial casino deployment, gambling promotion, or wagering advice.

## Experience principles

1. **Transparent mathematics:** expose the inputs and derived statistics behind the game.
2. **Presentation follows outcome:** determine results before animation and never alter them to create drama.
3. **Useful experimentation:** make configurations reproducible, validatable, importable, and exportable.
4. **Premium readability:** use realistic materials and atmosphere without sacrificing symbol recognition.
5. **Original identity:** evoke a broad tactical-thriller genre without copying any existing game or real-world organization.
6. **Responsible framing:** use virtual credits, avoid monetization pressure, and communicate variance honestly.

## Initial product boundaries

- Desktop-first responsive web application
- One five-reel base game and one defusal-themed bonus feature
- Local settings and statistics only
- Original generated and code-driven media
- No accounts, backend, payments, prizes, social casino economy, advertisements, or telemetry

## Core modes

### Play mode

An animated slot interface with virtual balance, bet controls, paytable, spin controls, win presentation, and a bonus sequence.

### Lab mode

An advanced configuration and analysis interface for reel strips, symbol weights, paytable values, feature rules, seeds, simulation size, and statistical results.

## Terminology

- **RTP:** expected stake returned as winnings over an extremely large number of spins.
- **Observed RTP:** the return measured over a finite simulation or play history.
- **Hit rate:** proportion of spins returning any win, based on the chosen definition documented with the metric.
- **Feature frequency:** proportion of spins that trigger a specified bonus feature.
- **Volatility:** the dispersion and shape of outcomes, reported through explicit measures rather than an unexplained label alone.

## Success criteria for the first playable milestone

- A seeded spin is reproducible.
- Pay evaluation is covered by unit tests.
- A user can inspect and change a valid configuration.
- A background simulation can run without blocking reel animation.
- The UI clearly distinguishes theoretical and observed statistics.
- The game contains no copied commercial assets or real-money functionality.
